## The chat shortcut

```text
!vblueprints
```

An administrator types it in chat. Blueprints opens on their screen on **Overview**,
fullscreen or in a window as they last chose.

That is the whole command. It takes no arguments, and it must be the **whole line**, after
trimming whitespace and ignoring case: `hello !vblueprints` is a sentence somebody typed, and Blueprints
leaves it alone rather than eating the line.

<Note>
The line is consumed for everybody who types it, authorised or not, so it never reaches the
room. If nothing opens, you are not an admin on this server. If the line does reach the room,
Blueprints is not running at all: see [Troubleshooting](/support/troubleshooting).
</Note>

## The console command

```text
vetra_blueprints
```

Run from the **client** console, in game. It does the same thing, and it takes an optional
section name so you can land where you want:

```text
vetra_blueprints versions
vetra_blueprints groups
vetra_blueprints remote
```

| Section | Argument | Key, once open |
| --- | --- | --- |
| Overview | `overview` | `1` |
| Versions | `versions` | `2` |
| Objects | `objects` | `3` |
| Groups | `groups` | `4` |
| Migration | `migration` | `5` |
| Restore | `restore` | `6` |
| Deploy | `deploy` | `7` |
| Remote Deploy | `remote` | `8` |
| Adapters | `adapters` | `9` |

Running it again while Blueprints is open brings the open interface forward, and a section
name moves it to that section. There is only ever one.

To close it, press `Esc` at the top of a section, press **Close** in the title bar, or run:

```text
vetra_blueprints_close
```

The interface itself is described in [The interface](/blueprints/interface).

## Who may open it

Blueprints is gated on Garry's Mod's own `IsAdmin` check, which is what most admin mods
(ULX, ServerGuard, SAM and others) set when they promote somebody. If your admin mod grants
admin, Blueprints grants access.

The gate is on the **server**, on every request the interface makes, not on the act of
opening it. An unauthorised player who somehow reaches the interface finds it empty: nothing
inside it is drawn until the server answers, and the server refuses.

<Warning>
Licensing and recovery commands are narrower still. `vetra_license_status`,
`vetra_license_activate` and `vetra_license_recover` require the **server console** or a
**superadmin**, because activation binds this machine to a licence and consumes an
allowance.
</Warning>

## If it opens but shows nothing

Opening the interface is deliberately not gated on your licence: an admin on a denied server
has to be able to reach the screen that explains the denial. If it is open and every section
is empty or refusing, read the notice at the top of the section and the licence state in the
status bar, then [Licensing and servers](/support/licensing).

## If it does not open

Blueprints needs the Chromium browser Garry's Mod embeds. Where the game's browser cannot draw
it, or the interface files did not arrive, Blueprints tells you in one chat line what happened
and what to do, and opens nothing. Your server is not affected.

See [Compatibility](/blueprints/compatibility) for which clients can run it, and
[Troubleshooting](/support/troubleshooting#blueprints-does-not-open) for each message.
